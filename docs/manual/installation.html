RadMon Installation Guide

Production Windows dijalankan dari app\RadMon.exe. Python tidak perlu dipasang di PC production karena runtime sudah dibundle.

Portable layout

RadMon\
  app\
    RadMon.exe
    docs\manual\
    grafana\
  config\
    .env.example
    .env
  runtime\
  archives\
  reports\

First run pada central PC 192.168.1.2

  1. Extract artifact RadMon-Windows ke folder tetap, misalnya C:\RadMon.
  2. Pastikan Docker Desktop tersedia jika Grafana lokal dipakai.
  3. Copy config\.env.example menjadi config\.env.
  4. Isi koneksi central MariaDB serta source gd50, gd52, dan gd38.
  5. Double-click app\RadMon.exe.

Source production

gd50 -> 192.168.1.50:3306 / ipradmon
gd52 -> 192.168.1.52:3306 / ipradmon
gd38 -> 192.168.1.38:3306 / ipradmon

Jangan mengganti source_id karena checkpoint/state menggunakan identity tersebut. RadMon tidak melakukan DDL pada database source production.

Migrasi konfigurasi lama

Jika instalasi lama memiliki .env di root dan config\.env belum ada, first run menyalin konfigurasi tersebut ke lokasi baru. File lama tetap disimpan. Target yang sudah ada tidak pernah ditimpa.

Upgrade

Tutup RadMon, backup folder instalasi, lalu pertahankan config\.env, runtime\, archives\, dan reports\. Ganti file aplikasi dari artifact baru dan jalankan kembali app\RadMon.exe.

Lifecycle

Satu proses RadMon menjadi owner untuk collector LAN, API, desktop Admin, alarm policy, archive lifecycle, dan bootstrap Grafana. Menutup desktop Admin menghentikan central service yang dimiliki proses tersebut.

Commissioning

Setelah instalasi atau upgrade, verifikasi source health, central MariaDB, Grafana, alarm Response/Silence, report/archive, dan konektivitas lapangan. CI/smoke-test bundle tidak menggantikan commissioning hardware nyata.
