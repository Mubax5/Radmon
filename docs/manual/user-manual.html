Manual pengguna

Panduan ringkas untuk login, monitoring, alarm, laporan, dan pemulihan aman. Manual ini menjelaskan perilaku aplikasi; commissioning jaringan, database, dan detector tetap wajib.

Pengguna Instalasi

Role dan prasyarat

Semua user RadMon wajib login. Remote anonymous tidak didukung. PIN sensitif terdiri dari 4–8 digit; password user terdiri dari 8–256 karakter.

Hak akses Control Plane
RoleAkses
ViewerRingkasan, Stasiun, Riwayat, Arsip, baca-saja.
OperatorViewer + Laporan, Alarm, response/silence, suppression, dan edit stasiun dengan PIN.
AdministratorOperator + Pengguna, Sistem, retry archive, dan editor Grafana lokal.

Akses RadMon

Dari client BRIN-NET yang mempunyai route ke server, buka URL HTTPS yang diberikan owner:

https://monitoring.example/app   Control Plane
https://monitoring.example/      Monitoring Grafana

Di PC server, Administrator dapat membuka Grafana native melalui http://127.0.0.1:3300. Port 3300 adalah loopback-only dan bukan alamat client remote.

Hasil yang diharapkan: setelah login, sidebar menampilkan menu sesuai role. Menutup browser tidak menghentikan server.

Monitoring, stasiun, dan riwayat

  1. Buka Ringkasan untuk status NORMAL, ALERT, ALARM, dan OFFLINE.
  2. Buka Stasiun untuk mencari nama, lokasi, atau SERID.
  3. Pilih stasiun untuk melihat pembacaan terakhir, threshold, timestamp, dan umur data.
  4. Buka Riwayat bila membutuhkan sampel historis, bukan hanya rolling monitoring window.

Offline station dapat menampilkan last reading bila pembacaan asli tersedia. Timestamp dan umur harus tetap asli; RadMon tidak membuat nilai, timestamp, atau garis trend datar untuk menutupi kehilangan data.

Alarm source dan policy central

Halaman Alarm menampilkan dua evidence: event policy central dan baris alarm source dari alat. Tombol response source hanya berlaku untuk baris source yang masih i_flag=0. Policy HIGH di central tidak dengan sendirinya menjadi target response source.

Menangani alarm source

  1. Periksa source, SERID, waktu event, nilai, threshold, dan source health.
  2. Pastikan baris yang dipilih masih aktif dengan i_flag=0.
  3. Pilih Response/Silence, isi Action, PIC, catatan/alasan, dan PIN.
  4. Kirim satu kali dan tunggu read-back dari source.

Sukses: backend menulis i_op, pic, note, dan i_flag=1 pada row (serid, dtoa) yang sama. Field legacy ack tidak diubah.

Jika gagal: ALREADY_HANDLED berarti row sudah ditangani. Timeout, row berubah, commit gagal, atau read-back gagal tetap merupakan error aktif. SQL/read-back tidak membuktikan buzzer fisik sudah berhenti; acceptance detector dilakukan saat commissioning.

Aktifkan suara alarm dari tombol halaman bila browser meminta izin. Suara browser atau notifikasi desktop bukan bukti penerimaan buzzer hardware.

Timed suppression

  1. Pilih stasiun pada tindakan operator.
  2. Isi durasi 1 menit sampai 24 jam, PIC, reason, dan PIN.
  3. Pilih auto-resume saat kondisi kembali NORMAL bila sesuai prosedur.
  4. Pastikan status dan waktu kedaluwarsa tampil.

Measurement dan dose tetap berjalan. Satu sesi menghasilkan paling banyak satu event SUPPRESSED. Untuk mengakhiri lebih awal, pilih Akhiri suppression dengan PIN dan alasan.

Laporan

  1. Buka Laporan sebagai Operator atau Administrator.
  2. Pilih stasiun, waktu mulai, dan waktu selesai dalam WIB.
  3. Pastikan rentang lebih dari nol dan maksimal 24 jam; tepat 24 jam diperbolehkan.
  4. Periksa pratinjau, lalu buat dan unduh PDF penuh.

Batas penting: preview maksimal 250 baris dan merupakan partial preview. PDF penuh memuat seluruh measurement sampai batas 50.000 measurement dan alarm sampai batas 10.000 alarm; job gagal bila data penuh tidak dapat dibaca, bukan diam-diam terpotong.

Timestamp PDF ditulis sebagai WIB dan nilai dose rate menggunakan dua desimal. Pada desktop, workflow tetap Preview → Print / Export PDF / Export CSV.

Jika Grafana menampilkan No data

Jangan langsung restart RadMon. Bedakan:

  1. Datasource error: Grafana hidup tetapi koneksi datasource MariaDB gagal. Administrator memeriksa Connections → Data sources → ipradmon → Save & test.
  2. Query berhasil tetapi hasil kosong: gunakan Inspect → Query/Response, lalu periksa SERID, UID datasource, query, dan current time window. Page Trends memakai Last 1 hour.

recent adalah rolling window tiga jam, recent_last menyimpan paling banyak 30 pembacaan asli per detector untuk tampilan offline, dan measurement adalah history authoritative. Last reading ditampilkan hanya bila data asli tersedia, dengan timestamp dan umur asli.

Layanan 24/7 dan pemulihan

Scheduled Task RadMon Server menjalankan app\RadMon.exe --server sebagai SYSTEM saat Windows boot.

  1. Gunakan shortcut RadMon satu kali.
  2. Periksa /health, task, port, log, Grafana, dan source health.
  3. Jika MariaDB, routing, TLS, atau hardware gagal, eskalasikan kepada pemiliknya.

Jangan membunuh semua proses Python, menghapus runtime, database, archive, atau report sebagai langkah pemulihan.

Untuk instalasi dan commissioning, buka Panduan instalasi.
